## 交付目标与边界

转换器覆盖代理人、音擎和驱动盘的来源盘点、身份映射、可重复转换与正式制品生成。在当前 core 公式能力范围内处理固定来源的全部可用静态效果；不能因为转换器或 effects 暂时缺少表达能力就把已有公式可以计算的效果列为暂不支持。

调用方从 data 读取规则和选项目录，提供角色基础属性、培养配置、有效选项及本次命中，通过 core 的 effects 模块得到这一瞬间的伤害。目录入口接收已有倍率与面板；完整配装、已结算面板和动作组装由更上层的[静态计算入口](../core/static-calculation.md)提供。两者都不模拟时间线。

超出现有 core 契约的新公式、未登记的来源版本、邦布、关卡环境与伤害流程预设不在本转换器的支持范围内；新公式即使已经出现在固定来源内，也遵循这一边界。固定来源内的空记录、身份缺失、缺少参数与新公式条目分别登记，不能通过删除条目、造零值或只公布已成功的分母制造全量覆盖。

现有 core 支持范围以本次 Fairy 基线的[公式规范](../core/index.md)为准。`sharpenDmgBonus` / `sharpenCritDmgBonus` 依赖的锐化/锐暴公式已于修订 9 接入；蕾米埃尔自身特殊虚曜对应的耀变已于修订 10 按具名机制接入，普通异常类仍不接受她作为异常强度提供者。上游通用 `special` 也不能通过新建任意最终倍率接口或暗乘基础伤害来绕过[特殊乘区边界](../core/factors/special.md)。已有耀变独立机制对应的 `specialMult` 等条目，应按明确来源映射到既有具体乘区；无法对应的条目记录原因。经开发者修订证据逐条核实的 `special` 条目按具名修正映射到既有乘区（修订 11 的壳中之灵），登记只针对该实体与记录，不构成全局把 `special` 当作异常增伤的规则。流明元素的标识和筛选属于已有耀变能力的适配，不能以 effects 的元素枚举尚缺 `lumiflux` 为由整体排除。

## 固定输入与证据

来源提交与主要资源路径沿用[静态快照规范](../effects/static-snapshot.md#来源与固定基线)。初始盘点的摘要、数量、身份对应及空记录见[来源盘点](../../plans/zzz-hp-static-inventory.md)；当前摘要以来源清单为准，实际转换结果以正式覆盖报告为准。

转换的输入包括固定提交的增益 JSON、加载规范化/实际读取/计算代码、经核对的身份与语义映射，以及当前 Nanoka 发布副本。增益 JSON 的 SHA-256 必须与来源清单一致；读取代码及其依赖也记录路径、提交和摘要。版本或摘要不符即拒绝生成，不能继续使用旧映射拼接新输入。

- 本机来源文件使用 raw 或仓库外目录，不加入 Git 或 npm 包；正式 definitions、映射规则、小型回归夹具和验证报告可以提交。
- 普通 build、test、check 和 npm 消费保持离线，不抓取上游，不要求 raw 存在，不改写 integrated。
- 生成器按需取得 integrated 的持锁已验证副本，随后只消费该副本；不得直接遍历受管理目录。数据管理边界见[来源整合规范](integration.md#数据管理状态的同步维护)。
- 不复制或执行上游应用的启动逻辑。差分只离线执行固定版本、依赖闭合且已检查的求值函数；上游函数的显示舍入与 Fairy 计算值分别记录。

## 身份与覆盖

正式规则的 `source.identity` 使用 Fairy 已有类别和 Nanoka 实体 ID；上游 ID、效果块 ID、局部效果 ID、资源路径和 JSON Pointer 保留为来源信息。

身份映射显式登记，按已核对的 ID 使用。名称仅用于核对和显示，不能在运行时模糊匹配、去标点或自动修正来源名称。相同局部效果 ID 出现在不同实体、效果块或影画位置时不得相互覆盖。排序位置是来源定位，不是唯一的长期身份；维护稳定的 `optionId` / `effectId`，来源数组重排只改变 pointer。

同一个音擎效果的五档精炼经结构核对后合并参数表；字段、适用范围或机制不一致时保留明确的档位条件与结构差异。不能按数组位置或名称相同就盲目合并。影画累计与精炼择一分别处理。

作用对象通常保存在选项 `target`；同一选项个别精炼档改变对象时，使用 `variants[].target` 明确覆盖。例如固定来源的聚宝箱精炼 1 自用、精炼 2–5 团队，保持该来源差异，不将第一档对象套用到全部精炼。

覆盖报告保留三个层次：

1. 实体：所有范围内来源实体，包括无效果记录、未匹配及占位项；另列 Fairy 中来源未收录的实体。
2. 来源位置：实际读取的每条效果及每个空 pack，保留类别、培养位置、pointer 与映射后的身份。
3. 消费选项：来源记录映射到哪些选项、规则或已登记的 core 输入参数映射，各自支持的档位、必需输入、限制及具名差异。由 core 唯一负责求值的参数映射也要有原始来源去向和验收，不能被报成无贡献后跳过。

来源效果记录状态使用 `converted`、`corrected`、`unsupported`；空 pack 使用 `no-effect-record`，占位实体使用 `placeholder`。`unsupported` 必须记录具体原因，例如 `missing-identity`、`missing-rank-evidence`、`missing-parameter`、`semantic-conflict`、`formula-out-of-scope`。状态和原因分开，禁止笼统的“引擎不支持”。一条记录产生多条规则、数条记录合为一个修改关系都允许，但每个来源位置必须有去向，且不能重复贡献。

缺少核心档位仅限制依赖该参数的选项/档位；同一实体其他已支持选项继续可用。部分支持不等于整个角色或全部影画已覆盖。

## 转换规则

### 读取路径与配置

转换顺序固定为原始资源 → 加载规范化 → 有效 pack/效果收集 → 上下文筛选与求值。先核对 `stores/calculatorBuffs.ts` 的实体加载、`calculatorUi.ts` 的 pack 规范化和 `buffEffect.ts` 的单条规范化，再按 `collectEffectsFromPack`、驱动盘两件套读取函数及其调用方选择表示。只有规范化之后仍有效的表示才能决定实际贡献；原始 pointer 与原值保留为来源，规范化结果和发生的变更另记，不把两者混成一份证据。

pack 收集通常是有实际效果的块优先，其次 effects，最后适用的旧汇总字段；驱动盘先执行自己的两件套规范化规则。兼容表示不重复累计，空块并不必然阻止回退。盘点的原始非空 pack 均选取效果块，但转换器仍要有加载规范化和回退分支的合成测试。显式覆盖旧 `skillCategory` / `skillSubcategoryId` 展开、异常适用标记补充、历史倍率修正清理及音擎回能字段迁移；不要求 Fairy 仿照上游对未知字段或非法数值静默补零。

固定数据复核发现 9 条驱动盘效果经单条规范化补充 `skillTargets`；不能因为原始数组缺失就丢弃技能范围。跨精炼标记归并另外改变家政员和心弦夜响各一条精炼 5 效果。来源分母继续按原始位置统计，不能用规范化后集合改写原始覆盖分母。

音擎异常适用标记还经过 `applyAnomalyFlagsToPack` / `withRefinementAnomalyFlags` 的跨精炼归并；应保留此读取行为，或者记录有依据的具名修正，不能只读当前精炼的布尔字段。影画读取 0 至当前影画，音擎读取固定增益和恰好一个精炼档。驱动盘按实际件数启用两件和四件选项，不能把不同装备槽位重复形成一份同套装效果。

上游默认开启、默认层数和 `convert.defaultBase` 仅作为可显示的预设。正式静态计算只应用明确选择的条件增益；转化缺少必需读取值必须失败。配置修改规则随培养配置生效，但只修改其关联的已选择效果，不增加一份完整强化贡献。

### 培养与选择

核心档位、影画和精炼遵循[已确认的培养记录](../effects/static-snapshot.md#培养档位的记录)。上游代理人记录没有显式核心等级字段，不能把所有常数推断为核心 7 档。依赖核心等级的参数必须有上游或补充来源的明确档位证据；只录已确认键，不能从默认面板推断、填零或插值。已存在的正确完整参数表继续保留。

潜能、姿态、梯度或其他额外条件可作为明确的静态选项表达；不能因为条目存于 0 影位置就认定它无条件解锁。互斥档位只允许选择一个；独立 buff 可以同时选择；叠层选项保留各自合法层数。关系通过经核对的条目映射记录，不以“同块”或“同名”作为互斥依据。

强化已有效果时优先生成目标明确的 modification，保留输入读取时机。耀嘉音 2 影沿用既有修正：修改核心 ratio / cap，删除语义上的“先加强化版、再负数抵消旧版”重复贡献，保持原有封顶结果和具名对比记录。丽娜等其他强化分别核对，不能仅看到负值就套用耀嘉音修正。

### 数值、对象和命中

映射表逐字段声明输入单位、输出单位、符号、阶段、归约方式和 core 落点，并覆盖盘点中的全部 52 种字段。映射对象包括：

- 初始/最终属性百分比、固定属性、暴击率/暴伤/穿透率；`pierce` 是贯穿力，不能当作固定穿透值。
- 增伤、减抗/无视抗性、减防/无视防御、易伤与失衡易伤；不同乘区不能仅凭字段名称合并。
- 普通、贯穿、异常、紊乱、乱流、异常结算、耀变及异化相关贡献；伤害类型和元素限制保持独立。
- 通用异常增伤进入普通异常、异放、乱流和耀变；通用异常暴击率/暴伤进入普通异常、异放和乱流。原始 scope、元素和招式条件继续限制其适用范围，不能因为字段名带有“异常”就仅保留普通异常，也不能扩展到紊乱。
- 基础倍率加算、倍率修正增量与特定基础伤害项。相同修正区的增量应先求和，再形成一次倍率；两项 +20%、+30% 不能错误变成 1.2 × 1.3。`special`、`specialMult` 与 `specialMultFactor` 分别核对，不混为一类。
- 持续时间对已支持异常/紊乱公式的数值影响、独立决算伤害项和贯穿力的属性依赖。这些可以通过固定快照和已有 core 计算的部分属于本次适配，不能一概归为动态模拟或新公式。
- 回能等本次伤害不消费的合法贡献应显式显示其适用边界；不能报告它提高了本次伤害。

转化使用 `max(0, source - initialBase) × ratio` 及可选 cap，分别换算源单位、阈值、系数和目标单位。`external`、`final`、`manual`、技能等级和角色等级的读取来源逐项保留；历史读取值用显式输入表达。缺失、零和显示预设不得混用，依赖环必须可诊断。

适用性覆盖自身/队伍、持有者与受益人、职业、队内恰好人数、元素、失衡状态、多个技能目标与追加攻击。队内人数使用固定版本的“恰好 N 人”语义。团队效果的元素筛选要区分受益者元素与本次命中元素，不能把两者全部替换成 `hit.element`。

技能定位保留来源 `skillSubcategories` 和 `followUpSkillRules` 中本次效果引用的身份、所属代理人和分类。一个命中可以符合多个标签；特定招式匹配不退化为整个技能大类。仅存在于名称/描述中的作用条件也必须在映射中明确体现或留下具体冲突记录。

### 派生输入与历史结算值

静态不等于所有数值都在本次实时读取。每个输入必须明确归属和结算阶段，避免把效果转化结果再次传入会做相同转化的 core helper。

- `world` 的通用属性使用 `GeneralStatInput`，支持基础值与调整分解，也支持 `settledInitialValue` 已结算初始值；两种模式不能混填。不能把最终面板整体放入 `baseValue` 后再次叠加属性百分比。基础阶段读取与新增初始百分比需要的输入见[面板与来源](../core/static-calculation.md#面板与来源)，缺失时明确报错，不反推原始属性。
- 目录路径的异化输入区分 `from-effects` 与 `settled` 两种模式：前者将选中且适用的完整异化系数贡献归约一次、加上基础倍率 1，再交给 core 的异化乘区；后者提供已经保存的最终倍率，直接复用，不读取当前蕾米埃尔属性或重新叠加当前异化贡献。模式不可混填。无异化时显式传入 `{ mode: "settled", multiplier: 1 }`；缺失历史倍率不能用 1 代替。低层入口同时保留 core helper 参数分支与 `{ settledMultiplier }` 分支，后者不再进行异化转化。
- 目录路径的耀变倍率保留本次招式基础倍率，由既有 core 耀变乘区唯一执行 `remielleAnomalyProficiency × anomalyProficiencyConversionRate`；目录准备层从已选择的对应规则取得实际精通读取来源和本次核心转换率，记录该参数映射的来源，不再把同一条转化额外输出为倍率加数或乘数。其他已确认的独立调整仍按规则提供。不能伪造“精通为 0”来绕过重复计算。
- 异常/耀变保存的来源攻击力、等级、异常精通等继续通过显式来源快照参与对应伤害项和乘区；不能用本次命中角色的实时属性替代。历史来源与当前命中者不同不是身份错误。目录入口必须能分别指定两者，并保留来源追踪。

目录输入中，`hit.damageItems[].statSource` 指定每项属性的实体与可选 `snapshotId`；`damage.anomalySource` 指定异常精通、穿透率的实体、可选快照与已保存等级。指定快照时，精通和穿透率都须存在于该快照 `attributes` 的 `current` 项；缺失报 `MISSING_SNAPSHOT`，不能用当前命中者属性或历史 world 兜底。防御区采用来源等级与穿透率；显式传入的固定穿透、防御调整及命中触发的减防等仍按各自输入或贡献处理。`actorSources` 同时登记当前参与队伍和历史提供者的身份；仅存在于历史快照的角色不计入当前队伍职业人数。

贯穿力使用 `0.1 × health + 0.3 × attack + independentSheerForce`。目录入口自动启用该依赖，`generalStats.sheerForce` 只提供独立部分的分解；没有独立加成也需显式提供全零分解。生命、攻击分别保留真实基础值与调整。直接填入已含生命/攻击转化的最终贯穿力会重复计算；保存快照的贯穿力则使用最终值，不再转化。

来源自转化若读取会排除自身贡献的阶段值，目录将其列为显式输入，避免把输出写回同一属性后再次读取；输入单位、阶段和预设见选项 `inputs`。条件描述中的潜能、姿态、资源或触发事实由调用方通过选择明确断言。已核实的互斥梯度通过 `exclusiveGroup` 校验，不能将全部条件项默认开启。

例如精通 500 产生的异化系数为 0.1，未有其他增量时最终倍率只能是 1.1；不能既转换成一条 0.1 贡献，又给 helper 传精通 500，得到 1.2。保存的倍率为 1.38 时，当前精通或 buff 变化不应改变它。耀变基础倍率 3.2、精通 400、换算率 0.002 的乘算结果为 `3.2 × (1 + 400 × 0.002) = 5.76`，精通贡献只出现一次；映射与上游结果存在差异时按来源规范登记具名差异，修改计算规则必须同步修订号与正式制品（见[修订 12](#修订-12耀变精通换算乘算口径修正)）。

目录入口为需要时间派生的基础伤害项提供明确的准备输入，而不是从一个最终 `damageMultiplier` 反推：

| 伤害项模式 | 必需输入                                                                                                                                                                         | 处理                                                                                                                                                                                                                                            |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 直接倍率   | 已准备的 `damageMultiplier`、属性来源和 itemId；可选携带 `originalAnomalyAttribute` 归属元数据（合法枚举与标准紊乱一致的七值：fire/electric/ether/ice/physical/auric-ink/frost） | 不反推持续时间；需要时间派生的已选条目缺少准备信息时报告缺失，不能无声跳过；元数据是来源归属声明，不据此重算传入倍率、不引入时间派生，也不要求无条件等于本次命中元素——存在真实归属 requirement 时（当前仅爱丽丝 standard-disorder）按原规则校验 |
| 标准紊乱   | 原异常属性、未含本次时间增益的基础持续时间、已经过的时间、属性来源和 itemId                                                                                                      | 加入本次适用时间增量一次，扣除已过时间并下限到 0，调用 `calculateStandardDisorderDamageMultiplier`                                                                                                                                              |
| 标准乱流   | 非风异常的 core profile、未含本次时间增益的基础持续时间、属性来源和 itemId                                                                                                       | 加入本次适用时间增量一次，调用 `calculateStandardVortexDamageMultiplier`；不使用紊乱的剩余时间语义                                                                                                                                              |

同一项只选择一种模式，派生模式不同时接受另一个手填最终倍率。这里的时间事实全部由调用方显式提供，不推进时钟；历史阶段的时间延长必须使用该阶段的明确输入。输入已经包含时间增益时不能再选择一份相同时间贡献。以感电剩余时间 10 秒为例，标准紊乱倍率为 17；错误地再次加 3 秒会变成 20.75，验收必须区分这两个场景。

多个时间派生项分别按自己的原异常元素筛选持续时间增量；`preparations` 按 `itemId` 返回实际时间增量和来源贡献。派生倍率先准备完成，再交给既有 `hit-adjustment` 按 `(原倍率 + Σadd) × Πscale` 求值，直接输入与等价的时间派生输入遵循相同顺序。直接倍率项上的独立决算使用 `role: settlement`，只接收决算加数；通用倍率修正区的加数先求和，再对准备完成的项乘一次。

## 正式制品与消费接口

正式制品放在 `packages/data/definitions/effects/`：

| 文件                   | 内容                                                                                                |
| ---------------------- | --------------------------------------------------------------------------------------------------- |
| `static.json`          | 统一 RuleSet，`ruleSetId: zzz-hp-static-effects`；包括正式贡献及其修改关系，revision 随语义修订更新 |
| `static-catalog.json`  | 同一 ruleSetId / revision 的来源、实体、选择选项、支持档位、必需输入、技能定位与具名差异            |
| `static-coverage.json` | 固定来源各实体/pack/效果位置到选项与规则的覆盖报告，以及具体未支持原因                              |

通过同名的 `@randomplay/data/definitions/effects/*.json` 显式子路径发布。根入口仍不加载定义 JSON，不增加运行时 core/effects 依赖；构建与解包继续逐文件字节复验。旧 starter / automatic 制品继续独立使用，新静态制品是完整消费单位；消费示例不得把它与重复定义同一机制的旧规则集直接拼接。

目录的逻辑结构固定为 `schemaVersion: 1`、`ruleSetId`、`revision`、`source`、`entities`、`options`、`skillTargets`、`differences`。`source` 记录固定提交及资源摘要；实体保留 Fairy 身份或明确的未匹配状态、上游身份及本次适用性所需资料。选项使用稳定 `optionId`，记录来源引用、作用对象、培养条件、开关/层数/互斥关系、必需输入、可用性及其 `effectIds`；耀变精通换算等由 core 求值的部分使用明确登记的参数映射，并按同样规则追踪来源、培养选值与唯一性，不开放任意字段路径写入。缺失档位或未支持原因保留在相应选项上。共享规则与目录的正式类型维护在 [shared 效果契约](../../../packages/shared/src/effects.ts)，由 core 重导出；引擎输入输出由 [core 类型](../../../packages/core/src/effects/types.ts)维护，不在文档或 data 中复制定义。

core 提供目录消费入口 `calculateStaticDamageFromCatalog`，组合目录校验、选项准备和 `calculateStaticDamage`：

- 输入包括 `definitions`、`catalog`、`bindings`、按 `optionId` 与 `bindingId` 标识的 `selections`、`actorSources`，以及 `world`、`hit`、`damage`、显式 `inputs`、`snapshots`、`atSeconds`。通用部分复用低层类型；`hit.damageItems` 扩展为上述三种准备模式，`damage.refringe` 支持明确的 from-effects / settled 语义，并允许分别提供历史伤害属性来源和当前命中者，不能机械照搬现有 StaticDamageInput 而遗漏这些必需输入。
- `actorSources` 将运行实体 ID 关联到目录中的代理人身份，以核对职业、队伍和装备适用性；不从实体 ID 字符串或显示名称猜身份。世界观察继续提供队伍关系和属性，二者必须一致。
- 先检查目录与规则集的身份、revision、引用闭合和选项身份，再展开选中规则及必要的修改依赖。只因未选择的独立条目缺档，不应阻止本次计算。
- 被选中的未知、不支持、未解锁、缺档、缺输入、身份冲突或互斥冲突选项返回有路径和来源位置的错误；不得被过滤后返回正常伤害。错误类型复用或扩展现有 `Result`，不抛出裸异常作为正常校验路径。
- 合法但不匹配本次命中的选项返回正常的零贡献，与不支持选项明确区分。
- 返回现有 `StaticDamageResult`，保留贡献来源、实际乘区与不适用贡献。原有低层静态入口保持可用。

完整可运行的请求数据见[打包消费夹具](../../../packages/data/test/fixtures/static-catalog-consumer.json)，其输入示例是啄木鸟电音两件套增加 0.08 暴击率。Node 消费方式如下；`request` 使用该夹具或同结构的 `StaticCatalogDamageInput` 请求字段：

```ts
import rawDefinitions from "@randomplay/data/definitions/effects/static.json" with { type: "json" }
import rawCatalog from "@randomplay/data/definitions/effects/static-catalog.json" with { type: "json" }
import {
  calculateStaticDamageFromCatalog,
  parseEffectRuleSet,
} from "@randomplay/core"
import type { StaticEffectCatalog } from "@randomplay/core"

const definitions = parseEffectRuleSet(rawDefinitions)
if (!definitions.ok) throw new Error(JSON.stringify(definitions.issues))
const result = calculateStaticDamageFromCatalog({
  ...request,
  definitions: definitions.value,
  catalog: rawCatalog as StaticEffectCatalog, // 目录入口仍执行运行时校验
})
if (!result.ok) throw new Error(JSON.stringify(result.issues))
console.log(result.value.expected)
```

Vite 使用普通 JSON 导入。具体招式通过目录 `skillTargets[].targetId` 填入 `hit.skillTargetIds`；入口校验所属代理人并展开技能大类和追加攻击标签。旧来源中表示整个大类的特殊 target ID 也应从目录显式提供，不根据显示名称猜测。

effects 的新增通道、属性读取或组合归约只能服务已核实的来源语义；类型、parser、运行行为、诊断、执行规范和实际消费同时修改。不能把 ZZZ-HP 对象透传到 core，或在 data 根入口嵌入计算逻辑。

## 生成、验证与交付

采用一套通用转换逻辑配显式实体/条目映射，避免为每个角色编写另一套求值器。内部生成入口为 `pnpm --filter @randomplay/data generate:static-effects <sourceRoot> <outputDirectory>`；源根目录包含固定仓库相对路径，输出必须是新的候选目录，并遵守[候选路径边界](consumption.md#静态发布与受管理目录边界)。先完成全部校验，再由维护者比较并安装三个正式制品；失败不得部分覆盖正式目录。不增加在线服务、API key 或终端用户配置。

```text
固定 ZZZ-HP 文件 + 身份/语义映射 + 持锁取得的 Nanoka 副本
                         |
                     离线转换器
                         |
          static.json + catalog + coverage
                         |
          effects 目录消费入口 → 现有 core 公式
```

转换语义或固定来源变化时，以同次生成的三个 JSON 作为验收和安装单位，并同步相关消费逻辑与测试。

验收要求：

1. 固定输入重复生成三个制品字节一致；在转换函数的合成测试中验证来源数组重排不改变稳定身份，正式命令仍拒绝重排后摘要不符的固定输入；错提交、错摘要、重复身份、丢记录和悬空引用均拒绝。
2. 完整核对来源分母与每个条目的去向，包括精炼合并、空记录、占位项、缺失身份及反向缺项；全部 52 种出现的字段都有明确处理策略。
3. 固定/叠层/转化分别测试零、边界、最大层、非法层、阈值和 cap；所有已提供精炼档、影画门槛、高影画不重复修改、核心缺档与合法零值都有覆盖。
4. 条件覆盖自身/队友、同名音擎的不同持有者、异职装备、恰好人数、受益者与命中元素不一致、失衡前后、多技能目标及追加攻击；层数、互斥和手工输入明确校验。
5. 批量对比使用固定上游的加载规范化、真实读取与求值行为，至少覆盖每个已转换来源位置的代表输入；关键阈值、所有精炼档和修改关系另做边界用例。包含 9 条旧技能定位及家政员/心弦夜响精炼 5 的实际样例。修正项保留两边结果与依据，不能用生成器的同一函数当作预期值。
6. 最终伤害通过当前 core 公式验算，并覆盖多个来源组合、属性依赖、同区倍率增量、多伤害项、异常快照与现有具名差异。必须验证异化/耀变的精通转化仅一次、已结算异化不受当前 buff 改写、异常历史来源与命中者分离、时间派生与直接倍率冲突，以及紊乱剩余时间和乱流持续时间的不同语义。效果值对比、最终伤害验算和上游整应用差分分别报告，不能互相冒充。
7. 正式 npm 包的 Node 与 Vite 开发/生产消费都实际读取新子路径并完成静态计算；根入口冷启动不请求这三个 JSON。断网、缺少 raw 的构建/消费仍可通过。
8. 执行根级 `pnpm check` 和 `pnpm --filter @randomplay/data verify:browser`；按变更范围完成必要数据管理验收。复用适用的已有结果，失败修复后只重跑受影响部分及最终必需门禁。

语义或覆盖变化时同步维护本页与正式覆盖报告，原始盘点保留其历史基线。发布按[包边界与联动发布](../packages.md)执行；涉及 integrated 或其管理契约的变化时，按[数据管理状态同步流程](integration.md#数据管理状态的同步维护)完成受影响工作区维护。
