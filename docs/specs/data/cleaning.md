# `@randomplay/data` 共享清洗规范

## 状态与范围

- 状态：草案，尚未实现清洗器
- 适用范围：从本地版本化原始缓存生成候选公开 JSON
- 公开文件与导入方式：[Data 包架构](index.md)
- 当前原始来源：[Nanoka 共享来源规范](../nanoka/source.md)

本规范只维护不同数据集共同遵守的清洗边界。每个数据集仍需独立规范，登记自己的来源成员、字段映射、
输出结构、排序规则、运行时校验和公开名称。

清洗成功只表示候选 JSON 满足本规范和对应数据集规范，不表示原始缓存成为权威快照，也不自动允许把结果
提交到 Git 或发布到 npm。首个数据集进入公开状态前，仍需按来源规范重新评审来源政策、再分发范围和制品
契约。

## 1. 处理流程

```text
明确版本的本地原始缓存
        ↓
数据集专属成员发现与提取
        ↓
来源结构、字段映射和跨文件验证
        ↓
内存中的完整候选数据
        ↓
确定性 JSON 渲染与原子替换
```

清洗器是离线转换工具，不执行网络请求，也不调用共享抓取器。缺少输入时必须失败，并提示使用方先按来源
规范获取对应缓存，不能在清洗过程中静默联网补齐文件。

## 2. 数据集规范的职责

每个数据集规范必须完整登记：

1. 稳定的数据集 ID、公开 JSON 路径、包根导出名和 TypeScript 类型名；
2. 来源 ID、允许的版本格式及输出中记录来源版本的位置；
3. 输入索引、详情文件、语言和其他必需资源；
4. 成员发现规则，不得依靠扫描缓存目录补充成员；
5. 消费的来源字段、允许的来源结构及字段到公开结构的映射；
6. 所有枚举、单位、数值范围、默认值和缺失字段行为；
7. 稳定 ID、数组的顺序语义、确定性排列规则、对象属性顺序和重复项处理；
8. 本数据集的支持范围、排除原因和不支持输入；
9. 运行时数据形状、清洗命令及必须覆盖的测试。

数据集规范不得通过“保留其他字段”“按上游原样处理”或开放参数对象绕过字段登记。需要保留的内容必须
有明确的公开语义。

## 3. 输入边界

### 3.1 明确版本

清洗命令必须先按来源策略验证明确版本字符串的格式，再用经过验证的值定位对应版本目录。来源缓存包含版本
清单时，清洗器还必须先验证清单结构和版本成员关系，再读取其他数据集输入；不能只检查字符串格式或目录
是否存在。对于当前 Nanoka 来源，清洗器读取对应版本目录中的 `manifest.json`，并确认目录版本属于
`zzz.available`。

`live`、`latest` 等通道名和 `available` 等版本集合字段不能作为清洗版本，也不能在清洗时重新解析为其他
版本。

候选数据必须记录实际使用的来源版本。包版本不能替代游戏数据版本。

### 3.2 成员发现

具有索引的来源必须从数据集规范登记的索引发现成员。详情目录中多出的旧文件不参与清洗，索引要求的详情
文件缺失时整次清洗失败。

数据集规范必须声明成员集合需要哪些语言或关联资源。清洗器只能使用已登记的输入路径，不能通过遍历目录
推断额外成员，也不能因为某种语言缺失而改用另一种语言填补。

### 3.3 原始缓存限制

当前 Nanoka 缓存可能来自不同抓取批次，不包含完整性证明或 HTTP provenance。清洗器必须验证自己需要的
索引、详情和跨文件关系，但不得把验证结果描述为对整个来源版本的完整证明。

清洗器不得修改、重排或删除原始缓存。输出路径由数据集规范固定，不接受任意文件系统路径。

原始 JSON 对象的成员名必须唯一。清洗器必须在普通 JSON 解码覆盖重复成员之前检测并失败，不能接受保留
首值或末值的解析结果。

## 4. 提取与归一化

### 4.1 字段白名单

公开数据只包含数据集规范列出的字段。来源对象新增了未消费字段时，可以在规范允许来源对象开放扩展的
位置忽略；已经消费的容器发生类型变化、缺少必需字段或出现未知枚举值时必须失败。

清洗器不能把整段未知来源对象复制到公开数据中，也不能提供 `metadata`、`extra` 或
`Record<string, unknown>` 一类逃生字段。

### 4.2 稳定身份

来源已有规范数字 ID 时，公开数据使用其十进制字符串作为实体身份。项目派生的记录 ID 必须由数据集规范
定义确定性构造规则，并使用与来源 ID 不冲突的命名空间。

本地化名称、描述、图标路径和数组位置不能充当稳定 ID。不同语言中的大小写、空格或 Unicode 表示差异也
不能产生新的身份。

### 4.3 本地化与跨文件核对

数据集规范必须区分机器字段和本地化字段。预期跨语言一致的 ID、枚举和数值需要逐项核对；名称、描述等
本地化内容分别保存，不用某种语言覆盖另一种语言。

如果清洗规则需要从自然语言描述提取结构化数据，数据集规范必须登记支持的文本形态、双语对应关系和失败
条件。无法识别的新表述视为不支持，不能依靠宽松正则、关键词猜测或默认值继续输出。

### 4.4 数值和单位

每个数值字段都由数据集规范定义单位、方向和值域。面向计算的百分比通常转换为小数，比如 `15%` 输出为
`0.15`；是否转换由字段契约决定，不能根据字符串中出现 `%` 自动推断。

输出数字必须有限。来源以 JSON `number` 编码的整数，在使用 JavaScript `number` 承载时必须处于安全整数
范围；超出范围时必须在发生精度损失前失败，不能把普通 JSON 解析得到的不安全数字再转成字符串。需要精确
保留的超范围身份或整数编码，必须由数据集规范登记为来源字符串，或使用能保留原始数字词法的解析方式，再
转换为十进制字符串。计算产生的 `-0` 统一输出为 `0`。清洗器不执行数据集规范没有要求的取整、钳制、插值
或精度修正。

### 4.5 闭合集合

公开枚举使用数据集规范登记的闭集。来源出现未知值时清洗失败，不能把未知值映射到 `other`、空字符串或
最接近的已知成员。

引用关系、配对限制和互斥关系由对应数据集规范逐项声明。仅验证两个字段分别属于合法闭集，不足以证明它们
的组合合法。

## 5. 覆盖与失败关闭

数据集规范必须定义自己的来源成员或内容片段分类边界。清洗过程中，每个进入该边界的输入都要得到以下
一种结果：

- `emitted`：已经转换为一条或多条公开记录；
- `excluded_by_scope`：数据集规范明确排除，并返回规范登记的稳定原因；
- `unsupported`：属于数据集目标，但当前规则无法无损表达。

`unsupported` 是清洗失败，不能发布缺少该内容的候选 JSON。`excluded_by_scope` 不能由清洗器临时决定；新增
排除原因必须先修改数据集规范。

当一个来源字段包含多个需要分别解释的内容片段时，数据集规范还要定义拆分边界。已识别的片段不能掩盖同一
字段中尚未识别的片段。

## 6. 确定性输出

相同的输入字节、清洗器字节、数据集规则和明确版本必须产生逐字节相同的 JSON。输出遵循以下共同规则：

- 使用 UTF-8，不写 BOM；
- 使用两个空格缩进，并以一个 LF 结束；
- 顶层和嵌套对象的属性顺序由数据集规范固定；
- 无语义顺序的数组按数据集规范定义的一个或多个稳定机器字段组成全序，不按本地化文本排序；
- 具有语义顺序的数组按数据集规范声明的来源顺序保留并验证，不能改按其他字段排序；
- 相同稳定 ID、相同关联键或其他声明唯一的值不得重复；
- 不写生成时间、绝对路径、临时目录、主机名或随机值；
- 不依赖文件系统枚举顺序、对象来源顺序或当前语言环境。

输出应由结构化候选值统一渲染，不能拼接 JSON 文本。清洗器重新读取自己生成的字节时，必须得到与渲染前
候选值相同的公开语义。

## 7. 写入与失败行为

清洗器必须先完成全部读取、转换、验证和渲染，再接触目标文件。候选字节与现有文件完全相同时不重写文件；
不同时先在目标目录建立临时文件，成功写入并关闭后再原子替换固定目标。

任何读取、解析、转换、验证或写入失败都必须：

- 返回非零状态；
- 给出数据集和失败阶段；
- 来源输入的读取、解析、转换或验证失败时，还要给出来源成员和失败字段或规则；目标文件 I/O 失败时，还要
  给出固定目标和失败操作；
- 保留原有公开 JSON；
- 不留下可被误认为有效输出的目标文件或部分文件。

清洗器不提供跳过错误、尽力输出或自动回退到旧版本的模式。

## 8. 验证要求

每个数据集的自动化测试至少覆盖：

- 最小合法输入和一组具有代表性的完整输入；
- 缺少索引、详情、语言或其他必需资源；
- 非法版本格式、版本清单无效及明确版本不属于清单可用成员；
- 非法 JSON、重复对象成员名、错误容器类型、缺失字段和未知枚举；
- 稳定 ID、重复项、无序数组的全序、语义序列的来源顺序及跨文件、跨语言不一致；
- 每种数值单位转换、边界值、非有限计算结果、`-0`，以及超出安全整数范围的来源 `number` 和字符串；
- `emitted`、`excluded_by_scope` 和 `unsupported` 三种分类，以及同一字段同时包含可识别片段和不支持片段时
  整次失败；
- 来源增加无关字段时的允许行为，以及已消费结构漂移时的失败行为；
- 相同输入重复运行产生相同字节，且内容未变时不重写；
- 任一成员失败时旧输出保持不变；
- 临时文件创建、写入、关闭或原子替换失败时返回非零状态；已有目标保持原字节，没有目标时继续不存在；
- 只使用索引发现的成员，不读取详情目录中的额外文件。

测试使用仓库内最小 fixture，不依赖网络或被 Git 忽略的本地 raw 缓存。真实缓存可用于人工核对，但不能成为
CI 通过的前提。

## 9. 非目标

本规范不定义：

- 任一具体数据集的字段结构或 TypeScript 接口；
- 通用效果、乘区、战斗状态或公式模型；
- 网络抓取、缓存更新或来源完整性证明；
- 图片和其他静态资源处理；
- 来源授权、再分发审批、npm 发布或 CDN 可用性验证；
- 数据版本迁移、多个游戏版本的运行时注册表或兼容层。

具体数据集只能在本规范范围内增加更严格的约束，不能放宽共同的失败关闭、确定性和输入边界。
