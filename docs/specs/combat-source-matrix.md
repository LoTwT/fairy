# 战斗来源矩阵规格（V1）

## 范围

本规格定义战斗相关来源在静态伤害计算中的默认归类方式。

共享基础类型与数值语义见 [shared-combat-types.md](./shared-combat-types.md)。
最终输入结构见 [combat-semantics.md](./combat-semantics.md)。

本规格解决：

- 某类来源默认进入 `panel`、`extras.modifiers`、`extras.overrides` 还是 `context`
- 哪些来源通常可直接从截图读取
- 哪些来源更适合作为辅助校验或回填

本规格不解决：

- 某个具体角色/音擎/驱动盘文本如何自动解析
- 完整战斗过程模拟
- 某个具体效果在特殊情况下是否例外归类

## 设计目标

- 先冻结“来源归类”，再做实体级处理后数据
- 让截图输入优先围绕最终面板工作
- 减少 `finalPanel` 场景下的重复叠加风险
- 为后续 `agent / w-engine / drive-disc / buff` 生成逻辑提供统一边界

## 结算桶定义

### `panel`

进入角色最终有效面板的数值。

特征：

- 通常能在角色详情或配装截图中直接看到，或可由装备明细稳定回填
- 后续会进入 `combat-semantics` 的 `panel`

### `extras.modifiers`

不进入最终面板，但在当前静态快照下额外参与计算的乘区。

特征：

- 多为条件性、战斗中生效或目标侧生效
- 后续会进入 `combat-semantics` 的 `extras.modifiers`

### `extras.overrides`

不是简单叠加，而是覆盖某个结算槽位的规则。

特征：

- 多为“以 A 取代 B”“使用某个快照值覆盖原槽位”
- 后续会进入 `combat-semantics` 的 `extras.overrides`

### `ignore`

当前静态伤害计算不直接使用。

特征：

- 与本轮伤害计算无关
- 或更适合保留在展示层、追溯层、评分层

### `context`

不属于角色最终面板，但属于本次计算稳定上下文的内容。

特征：

- 多为敌方或模式侧稳定数据
- 后续会进入 `combat-semantics` 的 `context`

## 归类规则

1. 如果某项效果会形成角色的稳定有效面板值，默认归入 `panel`
2. 如果某项效果不会进入面板，但会在当前快照下影响伤害，默认归入 `extras.modifiers`
3. 如果某项效果改写结算槽位，而不是普通叠加，默认归入 `extras.overrides`
4. 如果某项内容属于敌方或模式侧稳定上下文，默认归入 `context`
5. 如果某项内容只服务展示、评分或追溯，默认归入 `ignore`
6. 在外部调用中：
   - `panel` 以最终面板快照为准
   - 截图未直接提供的 `panel` 字段，可由装备明细回填
   - `extras.*` 仍需要由规则解析、手动勾选或战斗上下文补充
   - `context` 用于提供敌方与模式侧稳定输入，不与角色 `panel` 混合

### Agent

| 来源项                                               | 默认结算桶         | 截图可读性 | 说明                                 |
| ---------------------------------------------------- | ------------------ | ---------- | ------------------------------------ |
| 基础属性与等级成长                                   | `panel`            | 高         | 角色面板主数值的一部分               |
| 突破三围加成                                         | `panel`            | 中         | 形成最终面板，但通常不单独展示来源   |

## 当前明确约束

- `agentId` 不是截图直接提供字段，而是内部解析结果
- `cinemaLevel` 与 `potentialLevel` 分开，不混用
- `energyRegen` 统一承接截图中的“能量回复 / 能量自动回复”
- `penFlat` 与 `attributeDamageBonus` 缺失时允许从装备明细回填
- 当前角色按单属性处理；`attributeDamageBonus` 只保留当前角色属性那一项

## 未来扩展

- 如果后续确认某些来源类别需要更细粒度拆分，可在本规格中继续补子项，而不改已有桶定义
- 如果未来引入更多实体，优先先在本规格中补来源归类，再设计实体级处理后结构
