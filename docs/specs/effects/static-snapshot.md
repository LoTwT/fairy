# 静态快照增益数据与培养配置

状态：静态引擎和固定版本的批量数据接入已实现，包含部分档位表、跨单位转化、静态命中筛选、伤害通道、低层 `calculateStaticDamage` 与目录入口 `calculateStaticDamageFromCatalog`。正式制品、实际覆盖及未支持原因见[静态增益数据接入规范](../data/zzz-hp-static-effects.md)。公开类型与执行行为分别由 [types.ts](../../../packages/effects/src/types.ts) 和[执行契约](execution.md)维护。

## 计算范围

本轮计算固定配置、有效增益和命中信息下的伤害。调用方提供 buff 是否有效、当前层数或档位及必要的状态事实；effects 求解属性依赖、效果条件和贡献，静态入口组装 core 输入并返回最终结果。

- 首批目标是在现有 core 公式能力范围内完整接入可用的 ZZZ-HP 增益数据。已有公式对应的效果即使缺少 effects 通道或表达式，也属于本轮需要补充的适配能力，不能仅以当前 effects 不支持为由排除。
- 游戏更新带来的新公式、新机制列入后续范围，不要求本轮先扩展 core 才交付。每个未接入条目保留具体原因，缺失参数或未解决的语义冲突不得静默变成零贡献。
- 不从事件推导持续时间、冷却、自动叠层、能量消耗历史或召唤物返回过程；已有事件推进接口保留，不作为本轮新增规则的必经路径。
- 同一次计算期间配置与输入固定。用户改变装备、培养档位或 buff 选择后重新计算；配置阶段的参数修改仍然适用，不属于战斗时间线模拟。
- 静态快照仍可能需要效果施加时读取的属性。此时显式提供所需读取值，不用当前面板替代缺失的历史值，也不要求重放历史过程。

## 来源与固定基线

**ZZZ-HP 是增益数据与计算语义的第一信任来源。** Nanoka 用于基础资料、身份映射和缺失信息补充。冲突应保留来源与差异记录，不因来源不同自动用 Nanoka 或本项目推断覆盖 ZZZ-HP。

本轮核对基线固定为 ZZZ-HP 提交 `0df40c5bc38f8da7ed0f9eed6be87fb8155b8357`：

- [增益数据](https://github.com/Nie7bai/ZZZ-HP/blob/0df40c5bc38f8da7ed0f9eed6be87fb8155b8357/zzz-hp-backend/scripts/data/zzz-hp-calculator-buffs.json)
- [数据类型](https://github.com/Nie7bai/ZZZ-HP/blob/0df40c5bc38f8da7ed0f9eed6be87fb8155b8357/zzz-hp/src/types/calculator.ts)
- [效果求值与数据读取](https://github.com/Nie7bai/ZZZ-HP/blob/0df40c5bc38f8da7ed0f9eed6be87fb8155b8357/zzz-hp/src/utils/buffEffect.ts)

实现与对比用例使用同一固定版本；上游后续更新不自动扩大本轮验收范围。转换后发布本项目的数据制品，正常计算不在线读取 ZZZ-HP。

来源记录保留提交版本、原始实体及效果身份、资源路径和 JSON Pointer。规则仍使用本项目的稳定效果 ID；参数补齐或数据修订更新规则集 revision，不因当前选择的档位改变效果 ID。补充来源与本项目修正分别记录，不能伪装成未经修改的上游原值。

第一信任来源不等于两边任何结果都必须相同。已知问题保留为具名差异，例如[耀嘉音 2 影的负数抵消与封顶问题](examples.md#zzz-hp-的参考边界)；对比时记录输入、上游结果、本项目结果与修正依据，不能为消除差异默默改写已有正确规则。

## 定义与本次配置分开

| 数据           | 记录内容                                   | 计算时的职责                 |
| -------------- | ------------------------------------------ | ---------------------------- |
| 效果定义       | 参数表、公式、条件、修改关系和来源         | 根据配置确定本次规则与参数   |
| 来源绑定配置   | 当前核心等级、影画、音擎精炼等             | 每个来源只记录实际选择的档位 |
| 快照选择与事实 | 开关、层数、互斥档位、受益对象及显式读取值 | 提供当前已知的有效状态       |

独立 buff 可以多选；同一 buff 的互斥档位择一，叠层效果选择合法层数。默认开启、默认满层或默认读取值属于预设，不作为本次状态已经满足的证据。

基础属性与需要 effects 计算的增益贡献分开提供，避免给已含相同 buff 的面板再次叠加。来源身份、装备适用性、层数上限和互斥关系需要检查；静态模式不证明某个组合可以通过一段具体操作流程达成。

## 培养档位的记录

### 核心技能等级：参数查表

沿用 `coreSkillLevel` 的现有档位编号与 `by-rank` 参数概念。公式保留一份，随等级变化的系数或上限按明确档位键记录；不使用含义不明的数组下标。

以下参数片段表示：来源只确认了核心第 7 档的系数，常量上限已经确认，因此只记录已知项。

```json
{
  "ratio": {
    "kind": "by-rank",
    "rank": "coreSkillLevel",
    "unit": "ratio",
    "values": {
      "7": 0.35
    }
  },
  "cap": {
    "kind": "constant",
    "unit": "attack-points",
    "value": 1200
  }
}
```

部分档位表已同步到公开类型、解析和配置选值：

- 参数表只接受对应档位域内的键和有明确单位的有限数值；部分表必须至少有一项。
- 档位不存在表示缺失，不填零、不插值、不复用最高档，也不从默认面板数值猜测所属等级。
- 使用缺失档位的参数时明确报告缺档；合法数值零仍是已确认数据，与缺失不同。
- 必需参数各自完成选值后才能计算；部分参数有值不能使整条效果被误报为支持该档。
- 已有经核对的完整参数表继续保留，不因首批允许部分档位而删减。后续补档只增加对应键并更新 revision。

首批支持来源已经提供或本项目已经核对的档位，不将补全所有等级作为交付前提。

### 影画：累计解锁规则

沿用 `mindscapeRank`，取值为 0—6。基础规则与各影画新增规则分开保存，规则通过配置条件表达解锁门槛。选择 4 影时，门槛为 0—4 的适用规则都参与，各条规则只应用一次。

- 新增独立增益记录为独立贡献规则。
- 强化已有增益记录为 `modification`，以目标效果 ID 表达关系；按实际机制修改参数或已求值结果。
- 例如现有耀嘉音 2 影规则使用 `mindscapeRank >= 2`，在配置阶段给核心 `ratio` 加 `0.19`、给 `cap` 加 `400`，不重复叠加一份完整强化核心。已有表达见[基础效果如何被强化](index.md#基础效果如何被强化)。
- 只提高技能等级的条款交给技能配置与倍率选择处理，不能凭空变成一个固定伤害加成。
- 上游某阶的增益数组为空，只表示该位置未提供效果记录；不能据此认定该影画没有游戏作用，或声称该阶全部机制已覆盖。

核心等级选参和影画修改保持独立：先选本次核心参数，再应用已解锁的配置修改。0 影不是核心第 0 档，影画也不是当前 buff 层数。

### 音擎精炼：择一参数表

沿用 `refinement`，取值为 1—5。同一效果在各精炼档结构相同时共用一条规则，变化的数值存为参数表。例如固定基线中玲珑妆匣的每层伤害加成可记录为：

```json
{
  "damageBonusPerStack": {
    "kind": "by-rank",
    "rank": "refinement",
    "unit": "ratio",
    "values": {
      "1": 0.1,
      "2": 0.115,
      "3": 0.13,
      "4": 0.145,
      "5": 0.16
    }
  }
}
```

精炼 3 只取 `0.13`；当前有效两层时贡献为 `0.26`，不累计精炼 1—3 的数值。buff 层数另存于本次快照。上游 `refinementBuffs` 的数组位置须显式转换成精炼档位，不能直接当作本项目等级。

转换前核对各档的结构与含义。若某档改变适用范围或机制，保留带精炼条件的独立规则，不强行压成仅有数值变化的一张表。缺档处理与核心等级参数表一致。

## 转换与能力边界

转换器按固定版本的有效读取路径选取上游效果，避免把 `effectBlocks`、`effects` 和汇总属性等兼容表示重复累计。不同来源和效果块中的局部 ID 不直接充当全局身份；同一档位中的实际不同效果也不能仅因名称相同而去重。

数值按输入和输出的实际单位转换。例如暴击率 `8` 对应比例 `0.08`；属性转化、固定点数、阈值、上限和倍率需要分别处理，不能统一对所有数值除以 100。公式、条件和属性读取保留为定义，由快照求值；上游默认读取值单独保留为预设。

静态引擎已经补充下列能力；批量转换器须按具体来源条目使用并核对它们：

| 能力               | 需要满足的行为                                                                     |
| ------------------ | ---------------------------------------------------------------------------------- |
| 部分档位参数表     | 明确支持已记录档位，使用缺档时报告错误                                             |
| 跨属性、跨单位转化 | 明确源属性、读取阶段、目标单位、比例、阈值和上限；保留依赖分析                     |
| 静态适用范围       | 根据实际条目提供元素、伤害类型、技能范围等事实与筛选；编队和装备适用性由准备层提供 |
| core 输出适配      | 补齐已有公式所需的减防、易伤、失衡易伤、贯穿增伤及异常相关贡献等落点               |
| 倍率调整           | 区分加算、乘算和具体作用的基础伤害项                                               |
| 静态消费适配       | 将培养配置、buff 选择和命中信息组装到现有准备、状态导入、求值与 core 计算路径      |

具体通道、单位和消费映射见[执行契约的输出适配](execution.md#输出适配)，入口见[静态伤害计算](execution.md#静态伤害计算)。新增类型、字段校验、运行行为与消费映射一起验收。
