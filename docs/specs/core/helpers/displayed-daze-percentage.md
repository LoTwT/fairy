# 失衡比例显示值

失衡比例显示值帮助函数根据已经完成状态处理的累计失衡值和失衡值上限，计算怪物失衡条右侧显示的
整数百分比。规则来源为[原始攻略中的失衡比例说明](../../../references/zzz-data-introduction.txt#L155-L158)。

Nanoka 3.1 游戏文本确认使用 `Daze` 表示失衡值、使用 `maximum Daze` 表示失衡值上限，但没有提供
“失衡比例”的固定英文术语。`DisplayedDazePercentage` 是 core 基于已确认术语建立的组合标识，不应
反向解释为游戏文本中的固定英文名称。

## 公开契约

| 项目     | 定义                                     |
| -------- | ---------------------------------------- |
| 中文名称 | 失衡比例显示值                           |
| 公开函数 | `calculateDisplayedDazePercentage`       |
| 公开类型 | `CalculateDisplayedDazePercentageParams` |
| 结果语义 | 失衡条右侧显示的整数百分比               |
| 结果单位 | 百分比数值，`99` 表示 `99%`              |

```ts
export interface CalculateDisplayedDazePercentageParams {
  readonly accumulatedDaze: number
  readonly maximumDaze: number
}

/** 根据累计失衡值和失衡值上限计算向下取整后的失衡比例显示值。 */
export declare function calculateDisplayedDazePercentage(
  params: CalculateDisplayedDazePercentageParams,
): number
```

两个输入字段语义不同，因此使用参数对象，不使用位置参数或只包含数值的数组。函数返回普通 `number`，
不返回 `FactorResult`、`FormulaResult`、原始比例或失衡条状态对象。

## 输入语义

`accumulatedDaze` 表示目标当前失衡条中已经累积的完整失衡值。调用方必须先按业务时间线完成常规失衡
值、紊乱失衡值、直接累积、回复、自动回复、剩余容量和比例锁定等状态处理，再把状态处理后的非负
累计值传入。单次 `regularDazeFormula.calculate` 或 `disorderDazeFormula.calculate` 返回的 `value`
只是本次计算产生的失衡值增量，不能在没有当前失衡条上下文时直接解释为 `accumulatedDaze`。

`maximumDaze` 表示同一目标在当前结算时点采用的失衡值上限。它不是失衡比例锁定值；例如秽盾产生的
`99.5%` 锁定仍使用目标的完整失衡值上限计算，只由调用方限制可累积的 `accumulatedDaze`。敌人数据、
等级成长、强化状态和玩法效果如何确定最终上限，均在调用本函数之前处理。

两个字段都使用失衡值点数，不接收百分数字符串、已经除以上限的比例或单独的显示文本。

## 计算规则

```text
未取整失衡比例 = accumulatedDaze * 100 / maximumDaze
失衡比例显示值 = floor(未取整失衡比例)
```

计算优先按以下顺序执行：

1. 计算 `accumulatedDaze * 100`；
2. 将结果除以 `maximumDaze`；
3. 对未取整百分比执行 JavaScript `Math.floor`。

先乘以 `100` 可以避免 `29 / 100 * 100` 等先除后乘的计算因 IEEE 754 舍入而从整数边界下落。如果
`accumulatedDaze * 100` 发生中间溢出，必须先将 `accumulatedDaze` 和 `maximumDaze` 同时除以
`128`，再按上述顺序计算。`128` 是大于 `100` 的二次幂；这项缩放不会改变两者的数学比例，并确保任意
有限的 `accumulatedDaze` 在缩放后乘以 `100` 不会溢出。

函数不能改用未经缩放的先除后乘，也不能添加 epsilon 修正、固定小数位处理或其他格式化逻辑。缩放、
乘法、除法和向下取整遵循 JavaScript `number` 语义，公开返回前必须检查最终结果是否有限。只有完成
上述溢出安全计算后的百分比仍不是有限数值时，才按最终结果溢出处理。

返回值直接使用百分比数值，不使用 `0` 到 `1` 的小数比例。例如：

| `accumulatedDaze` | `maximumDaze` | 结果  |
| ----------------- | ------------- | ----- |
| `0`               | `1000`        | `0`   |
| `29`              | `100`         | `29`  |
| `995`             | `1000`        | `99`  |
| `1000`            | `1000`        | `100` |
| `1100`            | `1000`        | `110` |
| `1e307`           | `1e308`       | `10`  |

函数不把结果钳制到 `[0, 100]`。`accumulatedDaze` 大于 `maximumDaze` 时，只要计算结果有限，函数仍返回
大于 `100` 的整数。这项契约用于保留调用方传入的状态，不表示游戏中的失衡条可以正常超过 `100%`；
剩余容量、比例锁定和状态转换应在调用前处理，函数不能用静默钳制掩盖上游状态。

攻略没有给出失衡值点数或显示百分比的数值上限，因此不增加安全整数范围。超出安全整数范围时，函数
不承诺整数精度。

## 状态与显示边界

本函数只读取两个数值并计算显示百分比，不读取或修改失衡条。它不负责：

- 累积常规失衡值、紊乱失衡值或直接失衡值，处理失衡值回复和自动回复；
- 根据失衡值上限限制本次增量，或处理 `99.5%`、`99%`、`1%` 等失衡比例锁定；
- 判断目标能否累积失衡值，或是否临时无视常规失衡值；
- 判断失衡比例是否达到 `100%`，触发失衡状态，或处理触发标签、失衡持续时间和恢复；
- 计算目标失衡值上限，读取 Nanoka 数据，或解释游戏内部 `stun_*` 字段；
- 生成带 `%` 的 UI 文本，处理颜色、样式、动画或其他显示格式。

无法提供正数失衡值上限的目标不适用本函数。函数不是 `Factor` 或 `Formula`，不提供身份常量或默认
输入常量。

## 有效性与失败行为

| 失败条件                                    | 行为              |
| ------------------------------------------- | ----------------- |
| 参数不是非数组对象或为 `null`               | 抛出 `TypeError`  |
| 任一字段不是 `number`                       | 抛出 `TypeError`  |
| 任一字段是 `NaN`、`Infinity` 或 `-Infinity` | 抛出 `RangeError` |
| `accumulatedDaze` 小于 `0`                  | 抛出 `RangeError` |
| `maximumDaze` 小于或等于 `0`                | 抛出 `RangeError` |
| 计算得到的失衡比例显示值不是有限数值        | 抛出 `RangeError` |

多个失败条件同时存在时，不承诺校验错误的优先级。函数不得修改、冻结或替换调用方传入的参数对象。

## 代码组织

生产代码统一放在 `packages/core/src/daze.ts`，只包含失衡值公开帮助函数及其私有计算逻辑。可复用的运行时
断言继续放在 `packages/core/src/internal/assert.ts`，不得从包入口公开导出。

`packages/core/src/index.ts` 只负责重新导出公开函数和参数类型，测试保存在
`packages/core/test/daze.test.ts`。测试必须覆盖 `0%`、先除后乘会从整数边界下落的比例、小数比例向下
取整、`99.5%`、`100%`、超过 `100%` 时不钳制、极大有限输入的溢出安全缩放、输入不可变性、全部
失败行为和最终结果溢出。打包验证必须从安装后的包入口调用该函数并消费公开参数类型。
