## 2. 术语

英文标识用于区分概念，不预先承诺最终 TypeScript 类型名。

| 中文术语   | 英文标识             | 规范定义                                                                                           | 类别      |
| ---------- | -------------------- | -------------------------------------------------------------------------------------------------- | --------- |
| 公式       | `Formula`            | 一个由乘区组成并作为 core 公开计算入口的不可变业务定义，是选择、验证、执行和实施排序的顶层单元     | core 模型 |
| 乘区       | `Factor`             | 公式中独立求值并参与顶层组合的具名因子；定义自身输出、输入、上下文需求和乘区公式                   | 攻略原词  |
| 倍率       | `Multiplier`         | 用于乘法缩放的无量纲数值；它是数值，不是乘区                                                       | core 模型 |
| 乘区输入项 | `FactorInput`        | 乘区声明的具名业务输入通道，定义结算语义、单位和值域，可以接收零到多个输入值                       | core 模型 |
| 乘区输入值 | `FactorInputValue`   | 参与本次计算的一条具体数值记录，指向一个乘区及其中一个输入项，并保留来源身份                       | core 输入 |
| 乘区公式   | `FactorFormula`      | 使用当前乘区声明的上下文字段和乘区输入值求出原始值（`rawValue`）的确定性规则                       | core 模型 |
| 计算上下文 | `CalculationContext` | 一次计算所需且已经确定的攻击方、受击方、攻击和状态事实快照                                         | core 输入 |
| 计算输入   | `CalculationInput`   | 一次执行使用的公式、计算上下文和乘区输入值集合                                                     | core 输入 |
| 乘区结果   | `FactorResult`       | 某个乘区在一次计算中的完整结果，包含输入值、原始值（`rawValue`）、最终值（`finalValue`）和处理记录 | core 结果 |
| 计算结果   | `CalculationResult`  | 公式身份、结果语义和单位、公式原始值与最终值，以及有序的乘区结果                                   | core 结果 |

### 2.1 术语边界

- “公式”只表示常规伤害、贯穿伤害、异常伤害、异常积蓄值等由乘区组成、进入实施序列并作为 core
  公开入口的顶层业务计算。
  乘区内部等式属于“乘区公式”；属性换算等辅助等式不因出现等号而自动成为顶层公式。
- “乘区”表示具名计算定义；一次求值产生一个“乘区结果”。公式只使用各乘区结果的 `finalValue` 进行
  顶层组合。
- “倍率”表示 `Multiplier` 数值；产出倍率的乘区仍使用统一的 `Factor` 模型。
- “基础伤害区”和“基础失衡区”等名称属于具体公式，core 不将它们映射为单独的乘区类型。
- core 规范标识不得使用 `Zone`、`Bucket`、`Modifier` 或 `Resolver`。
- 乘区输入值必须直接满足目标输入项的语义、单位和值域；任意文本或外部数据记录不是有效输入。

## 3. 范围与包边界

当前 core 规范只覆盖：

- 公式、乘区、乘区输入项及乘区输入值的公共契约；
- 公式对乘区的有序组合；
- 单次、无状态、确定性的计算执行；
- 可复现的乘区结果和计算结果；
- [常规伤害公式](formulas/regular-damage.md)当前明确支持的规则。

当前不覆盖：

- Roadmap 中尚未进入具体规范的其他公式；
- 外部数据的获取、存储、解析和转换；
- Buff 持续时间、攻击序列、触发器和战斗时间线；
- 用户界面、优化器、CLI、网络协议和任意 JavaScript 回调。

包边界如下：

- `@randomplay/core` 的公开边界由公式、计算输入和计算结果组成。
- 调用方负责构造符合公式契约的完整计算输入。
- `@randomplay/core` 不依赖 `@randomplay/data`，也不假设输入来自任何特定数据源或上游处理流程。

## 4. 整体模型

```text
Formula
├─ 结果语义与单位
├─ 有序 Factor[]
│  └─ FactorFormula
├─ 顶层组合规则
└─ 公式级结果处理

CalculationInput
├─ Formula
├─ CalculationContext
└─ FactorInputValue[]
          │
          ▼
CalculationResult
└─ FactorResult[]
```

公式是唯一的顶层可执行单元。乘区是公式内部最小的独立求值单元，可以被多个公式复用，但不能脱离
公式成为普通调用方的另一套计算入口。

## 5. 公共契约

### 5.1 公式

每个公式必须完整声明：

| 属性         | 约束                                                               |
| ------------ | ------------------------------------------------------------------ |
| 公式身份     | 标识一个精确且不可变的公式定义；任一乘区契约变化都必须使用新身份   |
| 结果语义     | 明确结果表示伤害、失衡值、异常积蓄值或其他业务量                   |
| 结果单位     | 明确顶层组合后的结果单位                                           |
| 有序乘区     | 明确使用哪些乘区及其稳定顺序                                       |
| 顶层组合规则 | 明确如何使用全部 `FactorResult.finalValue` 生成公式原始结果        |
| 结果处理规则 | 明确顶层组合后是否应用取整、截断或其他已验证规则；无处理也必须声明 |

一个公式只有同时满足以下条件才有效：

1. 至少包含一个乘区。
2. 乘区身份在公式内唯一，顺序稳定。
3. 每个乘区及其乘区公式都有效。
4. 顶层组合规则使用全部 `FactorResult.finalValue`，且只生成一个有限的公式原始结果。
5. 结果语义和结果单位与顶层组合规则一致。
6. 公式级结果处理规则完整且不会产生非有限数。

内置公式必须显式定义，不能在执行时通过临时增删乘区拼装。普通计算输入不得改变公式结构。

以下规则用于判断变更属于哪一层：

| 变化                                                       | 归属                         |
| ---------------------------------------------------------- | ---------------------------- |
| 结果语义、结果单位、乘区组成或顶层组合规则发生变化         | 新公式                       |
| 某个乘区的输出、输入、上下文、内部算法、范围或精度发生变化 | 新乘区定义，并形成新公式身份 |
| 仅本次计算采用的乘区输入贡献发生变化                       | 新的乘区输入值               |
| 仅本次计算采用的上下文事实发生变化                         | 新的计算上下文               |

### 5.2 乘区与乘区公式

每个乘区必须声明：

- 在所属公式中稳定且唯一的身份；
- 输出语义和单位；
- 支持的乘区输入项及其结算语义、单位和值域；
- 需要读取的计算上下文字段；
- 没有输入值时继续求值、返回指定值或失败；
- 确定性的乘区公式，以及其中使用的固定常量、查表规则和派生计算；
- 有效范围、越界处理、精度规则及其执行顺序。

同一个乘区只有在输出语义和单位、输入项、上下文语义和结算时点、乘区公式、无输入行为、
有效范围及精度规则全部一致时，才能被多个公式复用。名称相同或代数外形相同不足以证明可以复用。

乘区公式只能读取：

- 当前乘区声明的计算上下文字段值；
- 目标为当前乘区的乘区输入值中的数值。

乘区公式不得读取其他乘区的临时结果，也不得访问当前时间、随机数、网络或进程级可变状态。

### 5.3 计算上下文与乘区输入值

计算上下文保存乘区求值所需的事实；乘区输入值保存由当前乘区输入项负责结算的独立数值贡献。具体
乘区契约决定二者的边界：

- 当前乘区声明某类数值贡献为输入项时，每条贡献必须作为乘区输入值进入；
- 当前公式明确排除某项属性或状态的形成过程，而乘区只读取其最终值时，该最终快照作为计算上下文
  事实进入；
- 同一项数值贡献不得既包含在上下文最终快照中，又作为乘区输入值重复计入。

游戏文本、展示文案和原始资料中的比例与倍率使用百分比表示。进入 core 计算的比例与倍率统一使用
归一化无量纲数值：`25%` 对应 `0.25`，`100%` 对应 `1`，`200%` 对应 `2`。调用方必须在构造
计算输入前完成转换；core 不执行该转换。

每个乘区输入值必须包含：

| 属性       | 约束                                       |
| ---------- | ------------------------------------------ |
| 输入值身份 | 在一次计算输入中稳定且唯一                 |
| 目标乘区   | 必须存在于本次选择的公式                   |
| 目标输入项 | 必须由目标乘区声明                         |
| 数值       | 必须是有限数，并符合目标输入项的单位和值域 |
| 来源身份   | 必须能稳定标识该数值的业务来源             |

来源身份只用于追溯和生成 `FactorResult` 中的输入记录。core 必须将它视为不透明标识，不得根据其
内容改变求值结果。

一次计算只选择一个公式，因此乘区输入值无需重复携带公式身份。一个乘区输入值不得同时指向多个
目标；调用方需要表达多个目标时，必须分别提供乘区输入值。

core 不解释条件或管理时间线。计算输入必须完整包含当前执行所需的事实和数值。

### 5.4 执行

一次计算必须按以下顺序执行：

1. 验证公式及其全部乘区。
2. 验证计算上下文的通用约束和各乘区需要的字段。
3. 验证乘区输入值身份，并按目标乘区和目标输入项路由。
4. 按公式顺序逐个执行乘区公式，得到每个乘区的 `rawValue`。
5. 对每个 `rawValue` 按乘区声明顺序应用有效范围与精度规则，得到 `finalValue` 并形成
   `FactorResult`。
6. 按公式的顶层组合规则组合全部 `FactorResult.finalValue`。
7. 应用公式级结果处理规则。
8. 生成不可变计算结果。

任一步失败都必须使整次计算失败，不得返回 `FactorResult` 或其他部分结果。相同公式、上下文和输入值
快照必须产生内容一致的 `CalculationResult`；失败时必须产生同一首要错误。

### 5.5 计算结果与乘区结果

成功结果必须包含：

- 公式身份与结果语义；
- 顶层组合后、公式级处理前的 `rawValue`，以及公式级处理后的 `finalValue`；
- 公式定义声明的结果单位；
- 与公式乘区一一对应且顺序一致的 `factorResults: FactorResult[]`。

每个 `FactorResult` 必须包含乘区身份、输出语义和单位、乘区公式直接产生的 `rawValue`、乘区级处理
后的 `finalValue`、稳定排序的输入值，以及发生的范围、钳制、取整或截断记录。全部乘区输入值必须
在且只在一个 `FactorResult` 中出现。

`CalculationResult` 及其中的 `FactorResult` 都是快照。返回后修改调用方持有的原集合，不得改变已经
返回的内容。

## 6. 不可变性与扩展边界

- 公式和乘区定义必须不可变。
- 普通计算输入不得携带公式或乘区函数。
- 内置公式不得依赖进程级可变 registry。
- 自定义公式及公式派生属于后续扩展；派生结果必须使用新身份，并在执行前完整验证。
- 任一乘区定义发生变化时，引用它的完整公式快照也必须使用新身份；结果必须记录该精确身份。
- 公式结构若要发生变化，必须在执行前形成新的完整公式快照，不能在一次执行过程中变化。
- 当前不引入通用表达式树、跨乘区依赖图、规则引擎或有状态执行器。

## 7. 具体公式规范要求

每个具体公式规范必须至少声明：

1. 适用范围和明确排除的计算类型。
2. 顶层等式、结果语义和输出单位。
3. 有序乘区组成。
4. 每个乘区的输出语义和单位、输入项、上下文、乘区公式、固定常量、查表规则、派生计算、范围和
   精度。
5. 历史快照与实时字段的结算时点。
6. 公式级结果处理及显示边界。
7. 成功、边界和失败验证用例。
8. 尚未验证规则的显式失败边界。

具体公式规范不得重复定义本文术语和公共执行流程。共享乘区出现第二个实际使用者后，只有确认完整
契约一致，才可以抽取为共享定义。
