## §1 项目目标与定位

### 1.1 一句话定位
为绝区零（ZZZ）玩家、攻略作者、AI 助手提供一个**贴合官方机制、可解释、可复现、可对账**的 1~3 代理人队伍**静态快照伤害计算核心**，并通过 CLI / AI plugin 暴露能力。

**计算器 vs 模拟器**：v2.0 仍是计算器，不是模拟器。输入"1~3 代理人 + 当前出手代理人 + 当前攻击段 + 已激活增益 + 敌人状态" → 输出"伤害与失衡值与异常 + 逐乘区分解 + trace"。**不模拟时间轴**。

### 1.2 用户问题
1. "这套驱动盘 / 音擎 / 影画值不值得换？" —— **配装比较**
2. "丽娜 30% 穿透率 vs V 位 24% 穿透率 vs 30% 增伤，哪个收益高？" —— **乘区收益分析**
3. "队伍配妮可减防 + 月城柳极性紊乱 vs 不配，能打多少 DPS？" —— **配队对比**
4. "我面板这样调整后，紊乱伤害会怎么变？" —— **属性异常 / 紊乱预估**
5. "首领有秽盾时贯穿伤害的优势具体多大？" —— **场景化伤害对比**

### 1.3 成功度量
- **正确性**：核心乘区计算与攻略示例（24% 穿透率收益 15.06% / 11.17% / 18.56%；60 级代理人攻击 60+ 首领默认防御区 0.4545、有秽盾 0.3165；2.2 倍 / 3.16 倍贯穿对比；攻略 §2.3.2 失衡恢复时间 8.61s / 6.42s）误差 ≤ 0.5%
- **完整性**：V1 覆盖攻略 PART 01 + PART 02（失衡值累积）+ PART 03（异常 + 紊乱）+ 队伍 1~3 + 队友增益乘区
- **可解释性**：CLI / API 输出每个乘区都附带"输入→计算→结果"+ 来源标注 + 攻略章节锚点
- **可复现性**：同一 snapshot.json + 同一 ruleSetVersion + 同一 dataVersion → 同一结果

## §2 范围边界

### 2.1 V1 In-Scope
- **常规伤害公式**（基础 × 增伤 × 暴击 × 防御 × 抗性 × 减易伤 × 失衡易伤 × 特殊乘区）
- **贯穿伤害公式**（无防御区，加贯穿增伤区）
- **真实伤害**（基于目标最大生命值；作为手动事件）
- **异常伤害公式**（含异常精通区 / 伤害等级区 / 异常增伤区 / 异常暴击区）
- **紊乱伤害公式**（七属性各自倍率公式 + 失衡等级区）
- **失衡值累积**
- **队伍 1~3 代理人**配队 + 队友增益乘区传播
- **`@randomplay/data`** 包（角色 / 音擎 / 驱动盘 / 影画 / 鸣徽 / 潜能激化 / 敌人 / 技能等级倍率，从 Excel + 爬虫 + 清洗派生）
- **`@randomplay/core`** 纯函数 + 逐乘区明细 + trace
- **`@randomplay/cli`** CLI 薄壳，JSON-only 输出
- **中英文双语**：英文为字段/函数命名权威，中文默认显示，`--lang en|zh`
- **构筑导入导出**（含 schemaVersion / ruleSetVersion / dataVersion / sourceVersion / gameVersion）
- **黄金集对账**（首批 20+ 锚点，攻略示例数值）

### 2.2 V1 Out-of-Scope
- **能量 / 闪能 / 喧响值循环模拟**（PART 04，仅作为静态属性 + 资源量值，不模拟时间轴）→ V2
- **秽盾完整状态机模拟**（PART 05，V1 仅静态修正 + 手动净除事件）→ V2
- **打断时序模拟**（PART 07）→ V2 或永不做
- **部位破坏时序模拟**（PART 06，V1 仅作为真实伤害手动事件）→ V2
- **邦布**（V1 schema 占位 `subordinate`，但不实现 handler）→ V1.1+
- **AI plugin / skill**（Claude Code Plugin 结构，V1 仓库不预留目录）→ V1.1
- **截图识别**（多模态模型，与 AI plugin 同期）→ V1.1
- **Web UI**（v1.0 设计已归档）→ V2
- **账号 / UID 抓取、抓包同步** → 永不做
- **真正"短链"分享服务**（V1 仅"压缩构筑代码 + 长 URL"）→ V2
- **创作者体验服 / 测试服数据** → 永不做（CONFIRM-11 锁定仅正式服）

### 2.3 V1 / V1.1 / V2 范围切分（决策记录）
- **V1 = `@randomplay/data` + `@randomplay/core` + `@randomplay/cli`**：核心计算能力可独立验证 + JSON 输出可复现
- **V1.1 = AI plugin（Claude Code Plugin）+ 截图识别（多模态）+ 邦布**：作为 V1 能力的消费者与扩展
- **V2 = Web UI + 时序模拟器 + 完整循环模拟**：v1.0 设计可平移作为基线

## §5 数据契约（M1 锁定项）

### 5.1 公式核心（沿用 v1.0 §5.1）
```
常规伤害 = baseDmg × dmgBonus × crit × defenseZone × resistance × vulnerability × dazeVulnerability × specialZone
贯穿伤害 = baseDmg × dmgBonus × crit × breachDmgBonus × resistance × vulnerability × dazeVulnerability × specialZone   // 跳过 defenseZone
异常伤害 = baseDmg × dmgBonus × anomalyProficiency × defenseZone × resistance × vulnerability × dazeVulnerability × damageLevel × anomalyDmgBonus × anomalyCrit
紊乱伤害 = 同异常 + 紊乱倍率（七属性各自公式）+ 失衡等级区
失衡值累积 = Σ baseDazeZone × dazeResistance × dazeInflict × dazeReceive × distanceDecay
真实伤害 = baseDmg（基于目标最大生命值 × 倍率）
```

### 5.2 三个前置契约 + 引擎硬契约（沿用 v1.0 §5.2，修订）

#### 5.2.1 统一属性快照（agentSnapshot in BattleSnapshot）
```typescript
agentSnapshot {
  inputMode: "panel" | "stats" | "mixed"
  rawInputs: { ... }                 // 用户输入（按面板字段 / 按词条字段）
  resolvedSnapshot: {                // core 唯一吃这一段（字段名为 D-11 示例，S2 最终锁定）
    attack, maxHp, defense, critRate, critDamage,
    penetrationRate, flatPenetration,
    anomalyMastery,        // 异常掌控（影响积蓄；ZZZ 官方 "Anomaly Mastery"）
    anomalyProficiency,    // 异常精通（影响伤害；ZZZ 官方 "Anomaly Proficiency"）
    impact, level, attribute,
    agentSpecialty,        // enum: attack/stun/anomaly/support/defense/rupture
    sheerForce?,           // 贯穿力（仅 rupture 角色；ZZZ 官方 "Sheer Force"）
    energyRegen?, maxEnergy?,
    automaticAdrenalineAccumulation?, adrenalineGenerationRate?, maxAdrenaline?,    // 命破角色 Adrenaline 系列
    ...
  }
  fieldProvenance: { [field]: "panel" | "stats" | "data" | "user-override" }
  overrides: { [field]: value }      // 显式覆盖项 (CONFIRM-13)
}
```

#### 5.2.2 BattleSnapshot（顶层 schema）
```typescript
BattleSnapshot {
  schemaVersion: "v1"
  ruleSetVersion: "rules-v0.1-attached-2026-05-04"
  dataVersion: "data-v0.x.0"
  sourceVersion: string              // 数据来源快照版本
  gameVersion: "ZZZ-2.x"             // 游戏大版本（与 sourceVersion 拆分，TechLead 提议）

  team: agentSnapshot[1..3]          // 1~3 名代理人
  activeActor: { agentId: string }   // 当前出手代理人
  attackSegment: AttackSegment       // 当前攻击段（V1 单段；多段后置）
  modifiers: TypedModifier[]         // 已激活的增益清单
  enemy: EnemySnapshot

  manualEvents?: ManualEvent[]       // 真实伤害手动事件（秽盾净除 / 部位破坏）
}
```

#### 5.2.3 TypedModifier（buff / debuff）
```typescript
modifier {
  id: string
  handlerId: string                  // 已注册 handler，不允许任意脚本 (CONFIRM-1)
  params: Record<string, any>
  appliesTo: TargetSelector          // self / team / agent[id] / enemy / global
  tagsRequired?: AttackTag[]
  bucket: MultiplierBucket           // dmgBonus | breachDmgBonus | anomalyDmgBonus | def-% | def-ignore | pen-% | resist-% | dazeInflict | ...
  priority: number
  source: { kind, name, version }    // 来源 (无来源 → dev-time assertion，FR-19)
  active: boolean
}
```

#### 5.2.4 配置导出版本字段族
```typescript
exportFile {
  schemaVersion: "v1"
  ruleSetVersion: string
  dataVersion: string
  sourceVersion: string
  gameVersion: string
  // 版本不匹配双路径（FR-21）
  originalRuleSetVersion?: string
  originalDataVersion?: string
  originalSourceVersion?: string
  originalGameVersion?: string
  build: BattleSnapshot
}
```

**版本不匹配处理（双路径，必须由数据契约层强制）**：
- **路径 A "按当前规则重算"**：保留 `originalRuleSetVersion` / `originalDataVersion` / `originalSourceVersion`
- **路径 B "保持原值只读"**：所有版本字段冻结，UI / CLI 只读态；禁止静默改写版本

#### 5.2.5 Handler 注入边界（CONFIRM-1）
- V1：仅允许"已注册 handler ID + 数据驱动参数注入"
- V1 不允许：build JSON / data 包内联 JS 代码
- 未来路径（V1.x+）：允许"外部受信任扩展包显式注册"，须固定 `EffectHandler` 接口、纯函数、无 IO / 网络 / 随机 / 时间依赖、必须输出 trace、带 manifest/version/source；CLI 默认不加载外部扩展，显式配置后再加载

#### 5.2.6 计算引擎硬契约（M1 进入/退出条件）
- 引擎必须返回**逐乘区明细**（每个乘区的输入、计算式、结果），不能只返回最终伤害
- 任何无来源（`source` 缺失）的 modifier 在结果明细中必须被标注为"⚠ 来源未标注"，**不得**作为可信数据静默通过
- `rawInputs → resolvedSnapshot → export → import → resolvedSnapshot` 必须 round-trip 不丢精度
- 分享 URL 编码若超过实现定义的长度阈值，必须显式降级到"压缩构筑代码"或"导出 JSON 文件"

### 5.4 关键派生关系（沿用 v1.0 §5.4）
- 属性最终值 = 初始属性 × (1 + 最终属性加成/降低) + 最终属性固定值加成；初始属性 = 基础属性 × (1 + 初始属性加成/降低) + 初始属性固定值加成（攻略 1.1）
- 贯穿力 = 攻击力 × C1 + 生命值上限 × C2，**每个命破代理人 (C1, C2) 独立配置**（仪玄为 0.3 + 0.1）
- 防御区 = 攻击方等级基数 / (受击方有效防御 + 攻击方等级基数)；等级基数表见攻略 1.4，60+ 锁定 794

### 5.5 显示与取整规则
