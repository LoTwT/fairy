### C 组：紊乱时长

期望顺序与固定口径：`duration` = 目录 `preparations` 汇总的时长贡献 → `remaining = max(0, base + duration − elapsed)`
→ 火紊乱按 `floor(remaining / 0.5)` 折档 → `倍率 = 4.5 + 档数 × 0.5`；延长只进入 `duration`。

| 状态 | 基础 / 已过 / 延长 | 剩余 | 倍率 | 边界含义                       |
| ---- | ------------------ | ---- | ---- | ------------------------------ |
| C1-0 | 10 / 0 / 关闭      | 10   | 14.5 | 未经过                         |
| C1-1 | 10 / 3.25 / 关闭   | 6.75 | 11   | 正小数剩余                     |
| C1-2 | 10 / 9.75 / 关闭   | 0.25 | 4.5  | 低于半档仍取基础倍率           |
| C1-3 | 10 / 10 / 关闭     | 0    | 4.5  | 恰好耗尽，不是零伤害           |
| C1-4 | 10 / 12 / 关闭     | 0    | 4.5  | 超过持续时间被钳制             |
| C1-5 | 10 / 13 / 开启     | 0    | 4.5  | 延长 3 秒后恰好耗尽            |
| C1-6 | 10 / 12 / 开启     | 1    | 5.5  | 基础时长已耗尽、延长部分仍有效 |

C1-3 与 C1-4 必须给出同一倍率与正伤害。C1-6 与 C1-4 是**同已过秒数的配对**：开延长剩余 1 秒
（两档补偿，倍率 5.5），关延长剩余 0（倍率 4.5）。把"基础时长耗尽后忽略延长"的错误实现两者
都会给出 4.5，因此这个配对与"延长贡献恰一次、攻击读数不变、三档按倍率比缩放"的断言共同
区分该错误。非法输入（`elapsedSeconds: -1`、`baseDurationSeconds: -10`）必须按 `INVALID_INPUT`
明确拒绝，不当作零剩余或零伤害。上游侧只保留已核对的纯函数结论：`defaultDisorderStats("火")`
的 450/50 与 `effectiveAnomalyDuration` 的 `max(0, …)`、`floor(x/0.5)` 对零、小数与延长后
剩余 1 秒给出同一折算。上游紊乱入口没有 `elapsedSeconds`，固定 `damageCalc.ts` 的取值为
`(useTriggerBase ? triggerPanel : panel).anomalyDuration || bonusPanel.anomalyDuration`：
**只有备用面板非零时，显式 0 才会被回退掉**，所以旧适配器的折入方式不保证表达"显式零剩余"；
这只是说明旧适配路径未经验证、不能外推为上游引擎无法表示零，零/小数/延长余量档的结论仍由
固定纯函数与 Fairy 公开契约支撑，不是上游界面或游戏实测。
