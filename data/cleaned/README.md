# Cleaned Data Outputs

Generated cleaned JSON is written here by S5 tasks. This directory is the
repo-level staging area for publishable data. Before publishing `@randomplay/data`,
run `pnpm --filter @randomplay/data sync-cleaned` to mirror JSON files into
`packages/data/cleaned/`, which is the actual npm package payload directory.

Rules:

- Files must be generated by `@randomplay/data` importers from source documents.
- JSON must include or reference source metadata sufficient for audit.
- No raw source JSON, HTML, JS, images, full Excel workbook, or bulk table dump
  belongs here. Normalized calculation-relevant source text is allowed only when
  it has source refs, hashes, and parser metadata.
- No hand-authored formal game data belongs here.

Current generated artifacts:

- `audit/v1-agent-source-candidates.json` — minimal Excel-derived source
  candidates for V1 team-modifier replay and V1.1 Bangboo numeric replay.
- `audit/nicole.acceptance.json` and `audit/yanagi.acceptance.json` —
  lo-user manual acceptance records for G22/G23 source-text mappings.
- `audit/mihoyo-buhflipexplode.source-conflicts.json` — manual audit
  resolution for the three historical Mihoyo/buhflipexplode Deadly Assault
  buff source conflicts, preferring buhflipexplode after nanoka lookup while
  retaining Mihoyo source trace.
- `golden/v1-replay-report.json` — source-backed V1 golden replay report.
  The current report includes the V1.1 G24 Penguinboo, G25 Sharkboo, and G26
  Plugboo numeric anchors plus G27/G28 nanoka runtime-primary proof anchors.
- `runtime/game-data.json` — Phase 4 nanoka runtime cleaned artifact. It must
  parse as `GameData`, set `runtimeCutoverReady=true`, use
  `GameData.sourceVersion=nanoka-zzz@2.8`, and fail validation if it references
  archived Excel/D-17/D-12 source IDs.
